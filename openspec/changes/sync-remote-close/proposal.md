# 远端关闭的会话，本端要如实变灰

## 为什么

在 B 窗口点掉一个 A 创建的终端后，A 那边的标签仍然是绿点、看着像活着，点进去却是死的。用户问的正是这件事：

> 如果在断开之后，删除了其中一个或几个 tab 呢，再连上之后怎么办？

根因在 `syncFromList` 的清理循环：

```ts
if (session.owned || seen.has(session.sessionId)) continue
```

`owned` 的会话被整段跳过，于是「远端列表里已经没有它」这件事在本端完全不生效。当初这么写是为了不误删刚创建、列表还没回来的会话，代价是远端关闭永远同步不过来。

## 怎么做

- `RemoteSession` 增加 `createdAt`，创建后 3 秒内的会话不参与"消失判定"，避免列表晚到造成假死。
- 清理循环拆成两支：
  - **自己创建的**：列表里没有 → 置为 `exited`、断数据通道、标签保留变灰。不擅自删用户的标签，但必须让状态诚实。
  - **镜像别人的**：列表里没有 → 直接移除（对方关的，留着无意义）。
- `existing` 分支补反向恢复：列表里又出现了 `exited` 的会话，说明上一轮是假死，拉回 `active` 并重连数据通道。

## 三种时序下的结果

1. **两端都在线，另一端删**：本端 3 秒内（实际是下一次列表广播）看到灰点，标签还在，点 × 才消失。
2. **本端离线期间被删**：重连时列表里没有它，本端不会凭空生出来，等于已经是删除态。
3. **本端离线期间另一端新建**：重连后自动挂上、镜像同一块 PTY。

删除本身不可逆：PTY 进程被宿主 kill，重连只能拿到"它没了"，拿不回滚动缓冲。
