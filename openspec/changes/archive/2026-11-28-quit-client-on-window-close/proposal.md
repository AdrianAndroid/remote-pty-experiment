# 关掉窗口，客户端就该从在线列表消失

## 为什么

在 Mac 上点左上角红叉关掉客户端窗口后，另一台电脑的在线列表里这条客户端还在，卡片显示「在线」，点进去还能看到它的终端。

根因是 Electron 在 macOS 上的默认模板行为：

```ts
app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit()
})
```

窗口全关，进程不退 → 与 relay 的 `/ctl` 连接一直挂着 → relay 认为这个客户端还在线，永远不广播下线。

用户的直觉是「窗口关了就是关了这个客户端」。而 rpty 的模型里，**在线列表 = 当前连着 wss 的客户端**，所以窗口关掉而进程还活着，列表说的就成了假话。

## 怎么做

- `window-all-closed` 一律 `app.quit()`，不再对 darwin 放行。关窗即退出客户端。
- `before-quit` 里挡住一次退出，先 `relay.disconnect()`（它会先发 `CTL_LEAVE` 让配对的另一端也知道，再关 ctl），落定后再 `app.exit(0)`，保证 relay 收到的是有序关闭而不是被 kill。
- 终端本身不受影响：PTY 全在本地 agent（LaunchAgent 常驻）里，客户端只是个观察者。关客户端 = 摘下画面，不是杀会话；重开客户端会重新认领宿主、把会话镜像回来。

## 效果

- 红叉关窗 → 另一端的列表里这条客户端立刻消失；正在看它的那端回到列表并收到「已断开中继」提示（这条链路已有）。
- 本机终端继续跑，重新打开客户端即可接着用。
- 与「客户端才是实体、断开不连坐」的模型一致：客户端下线 = 这个实体下线。
