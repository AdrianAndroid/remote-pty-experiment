# 变更：agent 给自己起一个持久名字，重启不变

## Why

现在节点标识是 `--node`，没给就取主机名短名。于是：

- 同一台机器起第二个 agent 必须手动想名字，否则两个节点撞成一个（后连的顶掉前面的）；
- 主机名改了就变成另一个节点，客户端按节点存的标签记录对不上，看起来像"标签丢了"；
- 名字不是它自己"认领"的，重启后是否同名取决于启动命令怎么敲。

## What Changes

agent 启动时自己解决身份，并落盘：

1. `--node` 给了就听 `--node`（显式优先，兼容手动部署）。
2. 没给就读状态文件里的 `node`；没有就**生成**一个：`<主机名短名>-<4 位随机 hex>`，写回状态文件。
3. `--name` 给了就用作显示名；否则用状态文件里的；再没有就用主机名。
4. 状态文件默认 `~/.rpty/agent.json`，可用 `RPTY_STATE` 指定（便于同机跑多个 agent）。

结果：**同一个 agent 重启、断线重连、重新配对，名字都不变**；同机多开各自唯一，不用手填。

## 客户端配合

两台的显示名撞车时，设备卡片自动补上 id 尾段（`zhaojiandeMac-mini · 7f3a`）区分；
名字唯一时不显示尾段，保持干净。

## 边界

- 老 agent（`--node default` 那种）不受影响：显式 node 直接生效。
- 删掉状态文件 = 换新身份，等于换了一台新机器（旧标签记录自然对不上）。
- relay 协议不变，`node` 仍是字符串。

## 验收

- 不带 `--node` 起 agent：得到 `主机名-xxxx`，重启后同名。
- 同机再起一个（不同 `RPTY_STATE`）：得到另一个唯一名字，两个节点同时在线。
- 客户端设备列表里两个都出现，卡片可区分。
