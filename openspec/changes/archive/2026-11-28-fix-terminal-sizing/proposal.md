# 修复终端排版：PTY 尺寸唯一权威 + 镜像端等比适配

## 为什么

三个体验问题指向同一处：**xterm 的行列和 PTY 的行列不是同一个值**。

1. 两个窗口看起来一样，内容不一样 —— 各自按自己的列宽折行，PTY 却是另一个宽度。
2. `claude` 这类全屏 TUI 打开后底部留白或被切 —— TUI 按 PTY 行数绝对定位，xterm 的 rows 比它多或少。
3. 被控端画面错乱、文字重叠、内容串行 —— 行列不一致时，光标绝对定位全部落错位置。

## 根因

| # | 位置 | 问题 |
| --- | --- | --- |
| 1 | 渲染层 `fit()` | 隐藏的标签页 / 还没布局的窗口上量出 0 尺寸，fit 给出 `10x5` 这种荒唐行列并发给宿主，PTY 被压坏 |
| 2 | relay | 创建端改窗口后只把 `SESSION_RESIZE` 转给宿主，其它控制端收不到；缓存里的 `last_list` 也不更新 |
| 3 | 客户端 | 镜像端的 `sizeLock` 只在 adopt 那一刻写入，之后不再刷新 |
| 4 | 渲染层 | 镜像端仍然 `fit()` 自己的窗口，再 `resize(lock)`；两次 resize 触发 reflow，且 fit 的行列和 PTY 不同 |

## 方案

**尺寸只由创建端决定，镜像端严格跟随。**

- 渲染层：`sizeLock` 存在时**不 fit**，直接 `term.resize(lock)`。容器装不下时对整层做 `transform: scale()` 等比缩小 —— 缩放不改变 xterm 内部字符度量，行列仍然正确。
- 尺寸链路：`SESSION_RESIZE` → relay 更新缓存并广播 `SESSION_RESIZED{session_id, node, cols, rows}` → 客户端 `onResized` → 渲染层 state → `sizeLock` 更新。
- 守卫三处：渲染层容器 < 40px 不 fit；客户端主进程拒收 `cols<20 || rows<5`；relay 同样丢弃异常值并打日志。
- 权威归属：创建端以自己最后一次 resize 为准，列表里的尺寸与本地不一致时**主动重发**修正宿主。
- 布局重算用 `requestAnimationFrame` 防抖，避免拖拽窗口时按中间尺寸算出的缩放比例卡住。

## 边界

- 镜像端窗口比 PTY 大：画面按 PTY 尺寸绘制，右下留白（字号不变，保证与宿主一致）。
- 镜像端窗口比 PTY 小：整体等比缩小，内容完整可见，代价是字变小。
- 缩放状态下鼠标坐标由 xterm 依 DOM rect 换算，点击定位仍然正确。

## 验收

- 两端同尺寸窗口：`xterm-screen` 均为 960×760，PTY 120×38。
- 全屏 TUI 测试：两端 `ROWS=38 COLS=120`，最后一行贴底，画面逐行一致。
- 容器压到 620px：缩放 0.6333，内容完整不裁切。
