# 变更：先连中继，再选设备，一对一会话

## Why

现在的交互是"连上 WSS 就等于进入所有机器上的所有终端"：relay 一推 `SESSION_LIST`，客户端就把每条会话都挂上数据通道自动镜像。结果是：

- 没有"列表"这一屏，用户看不到"有哪些机器可以连"。
- 两台机器看起来是同一个东西的两份拷贝，断开只能连着 WSS 一起断。
- 用户的心智模型是 **中继连接** 与 **与某台机器的会话** 两层，现在被压成了一层。

## What Changes

交互拆成三层状态：

1. **未连中继**：连接页（现有）。
2. **已连中继 / 设备列表**：列出所有节点（名字、在线状态、现有终端数）。WSS 保持常驻，只用来收节点上下线。
3. **已进入某台设备**：进入该节点的终端工作区（标签列 + 终端），只镜像这台机器的会话。

关键变化：**只有进入设备后才为它的会话建立数据通道**。没进入的节点，一条 viewer 都不占。

## 状态与动作

| 动作 | 影响 |
| --- | --- |
| 连上 WSS | 进设备列表，不自动 adopt 任何会话 |
| 点某台设备 | 只对该节点的会话开数据通道，进入工作区 |
| 侧栏「← 设备」 | 撤掉该节点全部画面（PTY 不动、不 kill），回列表 |
| 「断开中继 ⌘⇧D」 | 断 WSS，并按配对断开语义带走其它控制端 |
| 关闭应用 | 断 WSS，PTY 不动 |

## WSS 什么时候断

只在：用户点「断开中继」、退出应用、重连连续失败且用户放弃。进入/离开一台设备都不断 WSS —— 它是"哪台机器上线了"的唯一通道。

## 边界

- 一台设备都没在线：列表页显示空态与"等待被控端启动"的提示。
- 进入设备后该节点掉线：回到列表并标记该设备为离线。
- 断一对一不杀 PTY，重新进入设备时终端原样回来（沿用 detach 语义）。
- 已存在的会话归属、共享标记、尺寸锁定规则全部不变。

## 验收

- 连上 WSS：只出现设备列表，`viewers` 为 0。
- 进入设备：`viewers` 等于该节点会话数，标签出现。
- 点「← 设备」：`viewers` 归 0，列表回来，PTY pid 不变。
- 再进入：标签原样恢复，不重复。
- 点「断开中继」：`ctls` 减少且其它端按配对断开回到连接页。
