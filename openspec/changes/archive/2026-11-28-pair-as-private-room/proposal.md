# 配对即房间：一对一通话，房间外不可见

## 一句话

**配对不是"进对方桌面看一眼"，而是两个客户端关进同一个私密房间：房间里的一切双方平等共享，
房间外的任何人拿不到这些会话的列表、快照、字节。一方离开，房间立即关闭，双方一起回列表。**

## 现在是什么（与目标的差距）

| 维度 | 现在的实现 | 目标 |
| --- | --- | --- |
| 配对方向 | **单向**：A 点一下 B 就成立（`relay.py:806` `CTL_PAIR` 直接 `client.pair = {to, node}`），B 无从拒绝 | 双向：B 必须接受 |
| 配对关系可见性 | `pairs_summary()` 随 `broadcast_clients` 广播，所有人都知道"谁进了谁" | 只有房间内两人知道 |
| 会话可见域 | `SESSION_LIST` 无差别广播给所有 ctl，靠渲染层按 `owner` 过滤**显示** | 服务端按房间过滤，房间外**收不到** |
| 数据面 | `/d/<token>` 只验 token，谁拿到谁能看 | 验 token + 验请求者是否为房间成员 |
| 旁观 | 可以进任何在线客户端的桌面镜像同看 | **删除该能力** |
| 会话归属 | `session.owner`（某个客户端） | `session.room`（房间）或 `session.owner`（自己的私有桌面） |
| 一方离开 | 各自独立，另一方不受影响 | **房间关闭，双方一起回列表** |

## 模型

```
        ┌──────────────── 房间 room ─────────────────┐
        │ members = {A, B}      （排他：一人同时只在一个房间）│
        │ sessions = {s1, s2}                          │
        │   s1 跑在 A 的宿主，s2 跑在 B 的宿主           │
        │   两侧都能看、都能敲 —— 任何时候都是 1:1 通话     │
        └──────────────────────────────────────────────┘
                  ↑ 列表 / 快照 / 字节 / 配对关系只投给 A、B
        C 在线：看得到 A、B 在线，但看不到房间、看不到 s1/s2、拿不到 token
```

### 会话有两个可见域，不是一个

| 可见域 | 什么时候 | 谁能看 |
| --- | --- | --- |
| **私有**（`owner = 自己`） | 没进房间，在自己的桌面开终端（现在的单机用法） | 只有自己 |
| **房间**（`room = {A,B}`） | 在房间里开的终端，开在谁的宿主上都一样 | 只有 A 和 B |

服务端**两个域都要过滤**。现在只按 `owner` 在渲染层过滤，是"客户端自觉"，不是"服务端保证"。

### 房间的生命周期 = 两条连接的交集

```
  A 发起 → B 同意 → 房间 OPEN ──┬─ 一方 ws 断开 → 30s 宽限（断网重连可续）
                               │
                               └─ 宽限超时 / 任一方点「离开」/ 任一方关窗
                                       ↓
                                 房间 CLOSED → 另一方收到 ROOM_CLOSED → 双方回列表
                                              → 房间内终端销毁
```

- **30 秒宽限**：不做宽限的话，Wi-Fi 抖一下就把 `vim` 里没保存的东西一起带走。
  宽限内重连（同一 `client_id`）视为同一个房间继续。
- **超时即销毁 PTY**：房间关了就没有合法观看者，留着只是占资源、扩泄漏面。
- **排他**：已在房间里的人发起新配对一律拒绝（`4009 busy` 之类），
  避免"一个人同时在两个房间里"，那样"小黑屋"就不成立了。

## 状态机只有三个

整套东西收敛成三个状态，每个状态对应**一屏**，没有第四种：

```
  ┌───────────────────────┐   连上 relay     ┌───────────────────────┐
  │ S1 未上线              │ ───────────────→ │ S2 待配对              │
  │ 连接页：地址 / token   │                  │ 设备列表：谁在线       │
  │ 含 idle/connecting/    │ ←─────────────── │ 可看、可邀请、可进自己 │
  │ offline/error/detached │   断开 / 被踢     │ 的桌面（私有域）       │
  └───────────────────────┘                  └───────────────────────┘
                                                       │  ↑
                                        邀请 + 对方同意 │  │ 任一方断开
                                                       ↓  │
                                             ┌───────────────────────┐
                                             │ S3 一对一              │
                                             │ 房间工作区：共享标签   │
                                             └───────────────────────┘
```

| 状态 | 判据（实现上就看一个字段） | 界面上有什么 |
| --- | --- | --- |
| **S1 未上线** | `phase !== 'online'` 或 `detached` | 连接页 |
| **S2 待配对** | `phase === 'online' && !room` | 设备列表 |
| **S3 一对一** | `room !== null` | 房间工作区 |

现在的代码里其实有**五**个判断在拼这一件事：`phase`（idle/connecting/online/offline/error）、
`detached`、`activeNode`、`activeClientId`（我进的是谁）、`showWorkspace`。
归并成三态之后，`activeNode` / `activeClientId` / `showWorkspace` 全部消失，
换成服务端下发的 `room`。**屏幕由 room 决定，不再由三个本地布尔拼。**

两条推论，写下来免得以后再绕：

1. **`detached`（断开中继）不是第四个状态**，它是回到 S1 的一种原因，只影响连接页上写什么话。
2. **"我自己的桌面"不是第四个状态**，它是 S2 里的一个入口（私有域）。
   不进房间也能干活，但界面上仍然是"待配对"那一屏，只是里面有你自己的终端。

### 私有终端不带进房间

进房间时**从空开始**：房间里只有进房之后新建的终端，你在 S2 那个私有桌面里的标签不跟着进去。

理由：不这样的话，"点一下邀请"就等于把你机器上所有还开着的终端（可能正连着生产库、
跑着 `tail -f` 的日志）一次性摊到对方屏幕上。隐私默认要收紧，共享要显式。
真需要给对方看某条私有终端时，以后可以加"把这条终端带进房间"的动作，但那是显式操作。

## 列表上怎么显示正在通话的人

**留在列表里，挂一个「通话中」标签，灰掉不可点，不写跟谁在通话。**

| 做法 | 评价 |
| --- | --- |
| 从列表消失 | ✗ 列表的定义就是"谁在线"，突然消失等于谎报掉线；点不动也没解释 |
| 显示「已配对 · 与某某」 | ✗ 等于把小黑屋的门牌挂出来，第三方不需要知道 A 和 B 在一起 |
| **「通话中」+ 不可点** | ✓ 只暴露"这个人在忙"，不暴露对象；点一下 toast「对方正在私密会话中」 |

```
┌─ 在线客户端 ─────────────────────────────────────────┐
│  mini-a1b2        在线            → 可点（发起邀请） │
│  mbp-7e0d         通话中          ⊘ 灰、不可点       │
│  mbp-91fa         在线            → 可点             │
└──────────────────────────────────────────────────────┘
```

推论三条：

1. **当事人看不到这张列表**（他在 S3 里），"通话中"这个标记只服务第三方。
2. **状态必须实时**：一方断开 → 房间关闭 → 那行立刻恢复可点。30 秒宽限期内显示
   「通话中 · 重连中」，超时才转回「在线」——否则第三方会站在那儿白等一个已经不在的人。
3. **关闭后不留痕**：房间一关，标签就没了，不做"刚才跟谁聊过"的历史。

## 服务端要改的（relay）

1. **新增房间状态**：`rooms: Dict[room_id, Room]`，`Room = {id, a, b, sessions, created_at}`；
   `client.room` 互指。放进现有 `Client/Node/Session` 那套 dataclass 里，不新增并行字典
   （见 `consolidate-relay-state` 的教训）。
2. **配对改成三步握手**：`ROOM_INVITE`（A→relay→B）→ `ROOM_ACCEPT` / `ROOM_DECLINE`（B）→
   `ROOM_OPEN`（双方）。`CTL_PAIR` / `CTL_UNPAIR` 保留为兼容解析但不再产生房间。
3. **过滤所有会话出站消息**（这是本条变更的核心，一张表说清）：

| 消息 | 现在 | 改后 |
| --- | --- | --- |
| `SESSION_LIST` | 广播给所有 ctl | 按会话可见域拆开，只投给 owner 或房间成员 |
| `SESSION_CREATED` / `SESSION_CLOSED` | 广播 | 同上 |
| `SESSION_SNAPSHOT` | 定向投 viewer | 只投房间成员 |
| 数据面字节 | 投给所有 viewer | 只投房间成员 / owner 自己 |
| `NODE_*`、`clients` | 广播 | 仍广播（在线状态是公共信息） |
| `pairs` | 广播 | **改成只投当事人**，房间外看不到谁跟谁在一起 |

4. **数据面鉴权**：`/d/<token>` 建立 viewer 时校验 `client_id ∈ room.members` 或
   `session.owner == client_id`，否则 4003。
5. **房间关闭的广播**：给另一方发 `ROOM_CLOSED{reason}`，然后销毁房间内会话。

## 客户端要改的

1. **设备列表语义变了**：从"点进去看别人的桌面"变成"发起配对"。点一张卡片 = 发邀请，
   对方弹窗同意/拒绝。列表里不再显示"谁跟谁配对"。
2. **进房间 = 一个共享工作区**：左侧标签列 = 房间内所有会话（两边宿主上的都算），
   不再区分"我的桌面 / 别人的桌面"。
3. **`ROOM_CLOSED` 处理**：立刻拆数据连接、清标签列、回列表，提示"对方已离开"或"你已离开"。
4. **删掉旁观路径**：`enterDevice` 里"进别人客户端桌面镜像同看"的分支、
   `pairedWith` 那套"已配对"显示、`docs/10`、`docs/15` 描述的同看能力全部下线。

## 和 `data-plane-one-to-one` 的关系

**那份变更被本条取代，不实施。** 原因：它要的是"每条终端只允许一个 viewer"，
而房间模型要求"房间内两人都能同时看同一条终端"——否则就不是"通话"，是一人操作一人围观。

它当初的目的（别人不能旁观）由本条以更强的方式达成：不是限制 viewer 数量，
而是**从服务端就不给房间外的人发数据**。它里面仍有价值的部分（快照前增量排队、
`call_later(2.5, _force_ready)` 兜底）作为实现细节保留，不单独成为一个变更。

## 分期（每期都能独立验证）

| 期 | 内容 | 可验证的行为 |
| --- | --- | --- |
| P1 | relay 房间状态 + 三步握手 + 会话可见域过滤（含 pairs 不广播） | 用两个假 ctl 对着打：C 收不到 A/B 的 `SESSION_LIST` |
| P2 | 数据面鉴权（`/d` 校验房间成员） | C 拿 token 直连 → 4003；房间内正常出字节 |
| P3 | 客户端 UI：邀请/同意、共享工作区、`ROOM_CLOSED` 回列表 | 真机双客户端跑通；一方关窗，另一方回列表 |
| P4 | 下线旁观路径与相关文档 | `DevicesScreen` 里不再有"进入桌面" |

## 不做什么（诚实边界）

- **不做端到端加密**。relay 仍能看见所有字节，宿主机上的用户 `ps` 也能看见 PTY。
  本变更保证的是"**用这个 App 的其他客户端看不到**"，不是"物理上没人能看"。
  docs 16-18 描述的那套 PSK 加密仍未实现，需要另立变更。
- 不做"多人房间"。房间固定两人，`ROOM_ACCEPT` 时若任一方已在房间里直接拒绝。

## 风险

- **最痛的一处**：`SESSION_LIST` 现在是一份 `node.last_list` 缓存（`relay.py` 里 `node.last_list`），
  按房间拆分后要改成"按可见域分别拼装"，缓存策略要跟着变，容易写出"某个人看到别人的终端"这种
  隐私 bug。P1 必须补 `tests/test_relay.py` 的用例：三个客户端、一个房间，断言 C 的收件箱里
  永远没有房间内的 sid。
- 单向配对改成双向握手，旧的 `CTL_PAIR` 客户端（旧版本 App）会退化成"配不上"，
  需要客户端与 relay 同步升级。内网自用可接受。
- 会话销毁是不可逆操作，`ROOM_CLOSED` 的 30 秒宽限要写对，否则断网即丢工作。
