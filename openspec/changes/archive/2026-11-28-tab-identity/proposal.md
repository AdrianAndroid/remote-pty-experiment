# 变更：标签有稳定身份，重连后原样恢复

## Why

现在标签只在内存里：`leafId` 是进程启动时随机生成的，标题、顺序、当前选中都只活在渲染层。于是重连之后：

- 自己双击改过的标题被「终端 N」盖回去；
- 标签顺序按 relay 的 index 重排，跟人摆的不一样；
- 上一轮选中哪一个是丢失的；
- 换个客户端（不同 userData）连上来，看到的是同一批标签，分不清哪些是"我这个客户端的"。

用户要的语义：**同一个客户端重连，标签原样回来；换一个客户端，标签是干净的。**

## What Changes

给标签一把稳定钥匙：`sessionId`（relay 侧的会话身份，PTY 活着它就不变）。渲染层按「设备节点 + sessionId」持久化每个标签的元数据：

- 标题（用户改过的）
- 顺序（用户看到的位置）
- 当前选中

`leafId` 仍然只是本进程内的通信句柄，不再承担"身份"职责 —— 重启后可以变，标签身份不变。

## 存储

`localStorage['rpty.tabs.v1']`，按节点分桶：

```json
{ "<node>": { "active": "<sessionId>", "items": [{ "sessionId": "...", "title": "终端 3", "order": 0 }] } }
```

按 userData 隔离：换一个客户端（新 profile）就没有这份存储，自然是干净标签列。不做跨机器同步 —— 那是另一个需求。

## 边界

- PTY 已经不在的会话：恢复时按 sessionId 匹配不上，直接不显示（不复活幽灵标签）。
- 重命名 / 关闭 / 切换选中：立刻落盘。
- 只是"进设备/离开设备"：不落盘、不覆盖已有记录。
- 别人的会话（owned=false）也走同一套身份，重连后仍带「共享」标记。

## 验收

- 改标题 → 退出中继 → 重连 → 进同一台设备：标题还在。
- 摆过顺序、选中第 3 个 → 重启客户端 → 进设备：顺序与选中都还在，标签不重复。
- 清空 userData 的客户端连上：标签列从零开始，不继承别人的标题。
- 关掉一个标签再重连：它不回来。
