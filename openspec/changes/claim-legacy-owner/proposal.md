# 会话归属唯一化 + relay 状态落盘

## 为什么

「共享」标签的语义是「这个终端不是你开的」。现在有两类情况会让它在两端同时出现：

1. 归属机制上线前建的老会话，relay 里没有 owner 记录，两端都判成「不是自己的」，于是两个窗口都标共享。
2. `sid_owner` 只活在内存里，relay 一重启整张表清空，所有人都退化成「别人」。

用户的要求：标签只有两个角色，共享与非共享，同一个终端不能两端都共享 —— 即使两个客户端跑在同一台电脑上。

## 怎么做

- relay 记录一个 **默认认领者**：第一个带 `client=` 参数连上的控制端。所有没有 owner 的会话在下发列表时归给它，写进 `sid_owner`，此后不再变。
- `sid_owner` / `sid_index` / `default_claimant` 落盘到 `/data/relay-state.json`，容器重建后恢复。顺带把编号也钉住，避免 relay 重启后编号归零。
- 客户端逻辑不改：owner 非空且等于自己的 client-id → 非共享；否则共享。

## 效果

每个会话在整个系统里只有一个主人。主人那端没有标签，其余所有端（同机另一个窗口、另一台电脑）显示共享。标签的唯一性由服务端保证，不依赖客户端本地状态。

## 边界

- 认领发生在第一个连上的客户端，谁先连谁是主。若主客户端换了 userData 导致 client-id 变化，老会话会退回到「所有人都共享」，只能重开终端。
- 已关闭的会话不从 state 文件里删除（条目很小；删了反而丢掉重连后的归属）。后续可做定期回收。
