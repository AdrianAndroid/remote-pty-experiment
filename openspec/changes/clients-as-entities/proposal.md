# 客户端才是实体，设备是它认领的宿主

## 为什么

之前的列表叫「设备」，靠主机名判断"哪条是我"。用户指出这从根上就错了：

> 不应该是按客户端连接 wss 的，不应该是按主机连接 wss 的吧。每个客户端就是一个独立的个体。

同一台 Mac 上开两个客户端，它们共用同一个宿主 agent，但它们是两个独立的个体：
各自有固定名字、各自连一条 wss、各自出现在别人的列表里、各自断开互不影响。

## 变成什么样

1. 客户端连上 wss 才进入「在线客户端」列表；断开就立刻从别人的列表里消失。
2. 列表按 client id 聚合，每行一个客户端，名字是客户端自己的固定名字。
3. 自己那条标「我」、虚线、不可进入，并且固定排第一。
4. 进入别人 = 真连接：工作区顶部写的是**对方的客户端名字**，不是主机名。
5. 退出连接回到列表；对方机器上的终端继续跑。
6. 断开自己的中继不影响别人 —— 每个客户端是独立个体，不连坐。

## 宿主怎么认

客户端不再用主机名猜"我这台机器的 agent 是谁"，改成问本地 agent：

- agent 起来时在 `~/.rpty/agents/<node>.sock` 开一个 unix socket，
  并在同目录写 `<node>.json` 注册文件（node/name/hostname/pid/started_at/sock）。
- 客户端连上中继前扫一遍这个目录，按 `started_at` 升序逐个连 socket 发 `{"op":"whoami"}`，
  拿到自己的 host node id，握手时用 `host=` 报给 relay。
- 一台机器只有一个 agent，所以多个客户端认领到同一个宿主 —— 这是对的，
  它们是同一个宿主上的两个客户端，各自开自己的标签。

## 代价

`CTL_LEAVE` 不再广播 `PAIR_CLOSED`。老 relay 可能还会发，客户端保留处理但不依赖它。
