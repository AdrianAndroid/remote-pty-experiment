# 关闭语义：控制端关掉保留灰，宿主没了整体清

## 为什么

用户提出一条区分规则：

> 如果删除的是宿主，那另一个终端也删除。要是控制端，哪怕是删了也要保留。

现在的实现把两种「消失」混成一种：列表里没有就处理，只能靠 owned 猜。结果既会出现远端关闭同步不过来（已修），也没法表达「宿主整台机器没了」和「有人点了 ×」的区别。

## 两种事件，两种结果

| 触发 | 另一端应有的表现 |
| --- | --- |
| 任意控制端点 × 关闭某个终端（SESSION_CLOSE） | 标签保留、变灰、断数据通道；用户自己点 × 才移除 |
| 宿主消失（宿主进程退出 / 节点长期离线 / 宿主上报会话清空） | 该节点下所有标签一起移除 |

理由：控制端关掉的是「这一个终端」，信息有价值（是谁关的、什么时候没的），留着灰标签比默默消失更诚实。宿主没了是整台机器的终端全没了，逐条留灰只会堆一屏废标签。

## 怎么做

**relay**

- 收到 `SESSION_CLOSE` 时：从各节点 `last_list` 里摘掉该会话（否则新连上的客户端会 adopt 一个死会话），并广播 `SESSION_CLOSED {session_id, node, reason:"ctl"}`。
- 收到宿主发来的 `HOST_EXIT`（宿主正常退出前主动上报）：清空该节点 `last_list`，广播 `NODE_GONE {node}`。

**客户端**

- `SESSION_CLOSED` → 只置灰、断通道、保留标签（不再按 owned 分岔）。
- `NODE_GONE` → 移除该节点全部标签（新增 `session:removed` IPC）。
- `NODE_OFFLINE` → 先置灰（可能只是网络抖动）；**60 秒内没回来**按 `NODE_GONE` 处理，覆盖宿主被 kill -9 / 断电。
- `syncFromList` 的清理统一为「列表里没有 → 置灰保留」，删除只由 `NODE_GONE` / 离线超时触发。

**agent**

- 正常退出（SIGINT/SIGTERM/异常收尾）前发一条 `HOST_EXIT`，让另一端立刻清屏，不用等超时。

## 边界

- 宿主被 `kill -9` 或断电时发不出 `HOST_EXIT`，只能靠 60 秒超时兜底。
- 节点短暂断网又恢复：60 秒内标签保持灰色，恢复后 `SESSION_LIST` 回来会重新拉活（`active`），不会误删。
- 标签删除后若会话其实还活着（宿主恢复），下次列表会重新 adopt，标签会重新出现，代价是丢重命名。
