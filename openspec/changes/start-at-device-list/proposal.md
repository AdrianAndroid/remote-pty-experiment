# 启动落点：停在设备列表，不在别人的桌面里

## 为什么

用户打开客户端，看到的是**六个标签的终端**，而不是「谁在线、我和谁配对」那一屏。这不是匹配错，
是渲染层有两条自动行为叠在一起，把两屏都跳过了：

| 自动行为 | 位置 | 现象 |
| --- | --- | --- |
| 上线即进自己的桌面 | `App.tsx:655-663`（`ownEnteredRef`） | `client.host` 一非空就 `enterDevice`，设备列表整屏被跳过 |
| 空桌面 0.7 秒后自动建终端 | `App.tsx:513-532`（`autoCreatedRef`） | 桌面里没标签就 `createSession`，未经询问在宿主上 spawn 一个 shell |

第一条在 `docs/34-client-identity.md:157` 里被记成特性（"连上中继后自动进自己的桌面"）。
但它有两个副作用，用户实测撞上了：

1. **"谁在线 / 我和谁配对"变成不可见**。用户的原话是"并没有人跟它匹配，为什么停在了会话界面"——
   配对这件事本来是这套系统最需要被看见的状态，却被启动落点藏了起来。
2. **新客户端会凭空开终端**。一个刚建的 `client-N` 从没建过会话，上线 → 进空桌面 → 0.7 秒后
   宿主上多一个 shell，用户什么都没点。

## 改成什么

| 场景 | 现在 | 改后 |
| --- | --- | --- |
| 启动、连上 relay | 直接进自己的桌面（有 6 个标签就显示 6 个） | **停在设备列表**，显示在线客户端与配对关系 |
| 想干活 | 已经在桌面里 | 点「我这台电脑」/ 点某台设备 → 进桌面，标签照旧恢复 |
| 进到没有终端的桌面 | 0.7 秒后自动建一个 | **显示空状态**（"还没有终端 / ⌘T 新建"），等用户按 |
| 别人配对进来（`pairs.to == 我`） | 自动进自己的桌面 | **保留**。这是对方显式动作，跟"启动落点"不是一回事 |

保留的东西，一个都不少：`owned-sessions.json` 里的标签仍然在进桌面时按 `sessionId` 恢复；
选中项、顺序、标题都在；只是恢复的时机从"启动时"变成"点进去时"。

## 怎么改

1. 删掉 `App.tsx` 的 `ownEnteredRef` 及"上线即进桌面"那个 effect（`onOpenMine` 里的赋值一并删）。
2. 删掉 `App.tsx` 的 `autoCreatedRef` 及"空桌面自动建终端"那个 effect；`autoCreatedRef` 的
   8 处赋值全是这个开关的配套，一起删，不留死代码。
3. 空状态那一屏已经有了（`visibleSessions.length === 0`），不改。

## 风险

- **多一次点击**：每次启动要先点一下才进桌面。这是本轮要付的代价，换来的是"在线与配对可见"。
  若以后觉得烦，改成"记住上次关窗时的位置"只需读一个 UI 状态，不影响本次结构。
- **`detached` 语义不变**：主动断开中继仍回到连接页。
- 没有协议改动、没有 relay / 宿主改动，纯渲染层。

## 回滚

`git revert` 单个 commit 即可，无状态文件格式变化。
