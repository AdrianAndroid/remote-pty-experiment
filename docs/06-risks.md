# 06 · 风险、合规与排查

---

## 1. 合规风险（最高优先级）

**本质**：本方案实现的是「从家远程控制公司办公设备上的 shell」。技术上它避开了进程特征检测，但**没有改变这件事的性质**。

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 违反公司 IT 政策 | 多数企业禁止未经审批的远程访问、外联隧道 | 部署前书面确认；不确定就不用 |
| 安全审计告警 | 持续到外部域名的 wss 长连接，流量侧仍可能被网关记录 | 只连自有域名；不在高峰时段长挂；用完即停 |
| 数据外带嫌疑 | 能通过终端读取公司文件 | 只读必要项目目录；不做批量导出 |
| 责任归属 | 一旦发生数据事件，私建通道会成为首要追责点 | 保留书面审批记录 |

**代码层强制位**：agent 启动时必须显式设置

```bash
export AUTHORIZED=1   # 表示已获得公司授权
```

未设置时 agent 拒绝启动并打印提示。这不是安全机制，是**防自己一时冲动**的提醒。

## 2. 技术风险

| 编号 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R-01 | 公司网关封锁非常规长连接 | 连接频繁被切断 | 应用层心跳 + 指数退避；必要时降到纯 HTTPS 轮询模式（退化方案） |
| R-02 | EDR 对 `python3` 出站长连接告警 | 进程被终止或人工约谈 | 缩短在线时长、按需启停；不做常驻 |
| R-03 | 公司机无法 `pip install websockets` | agent 起不来 | 内联 vendored 单文件；或用标准库 `socket` + 手写 ws 握手（成本高） |
| R-04 | token 泄漏 | 他人可连上拿到 shell | 双 token 分离；定期轮换；relay 侧限流与 IP 白名单 |
| R-05 | relay 单点故障 | 两端同时断线 | 各自自动重连；relay 由 systemd 拉起 |
| R-06 | 内存泄漏（长跑 PTY） | agent 占用上涨 | 会话上限时长（如 8 h 强制重建）；内存监控 |
| R-07 | base64 膨胀导致大输出卡顿 | `cat` 大文件时 UI 卡 | 单帧 64 KB 切分；前端写入节流 |
| R-08 | 中文/emoji 跨帧断裂 | 乱码 | 全链路不做文本解码，纯字节透传 |

## 3. 安全加固清单

- [ ] 全站 HTTPS，TLS 1.2+，证书自动续期
- [ ] nginx 层限制 `location /ws` 的来源 IP（若家宽 IP 固定）
- [ ] relay 只监听 `127.0.0.1:8765`，绝不监听 `0.0.0.0`
- [ ] 双 token 随机 32 字节，来自环境变量 / systemd `EnvironmentFile`，权限 `600`
- [ ] 登录 shell 使用普通用户，不 root
- [ ] 不在 shell 里保存明文密码；`sudo` 依赖系统原有机制
- [ ] 日志脱敏：不记录 `data` 帧内容，只记元信息
- [ ] 家端浏览器不使用公共设备

## 4. 故障排查手册

### 4.1 agent 连不上

```bash
# 公司 Mac
curl -v https://your.domain/ws            # 期望 426 Upgrade Required 或 400
python3 agent_mac.py --debug              # 看握手与 auth 返回
```

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Connection refused` | nginx 未监听 / 防火墙 | 云主机 `ss -lntp \| grep 443` |
| `403` | nginx 拦截 | 检查 `location /ws` 配置 |
| 握手后立即断 | `auth_err` | 看 agent 日志的 `reason` |
| 连上但无输出 | PTY spawn 失败 | 检查 shell 路径、`TERM` 环境变量 |

### 4.2 连上但终端空白

1. 云主机上 `ss -lntp | grep 8765` 确认 relay 活着
2. agent 日志是否出现 `SPAWN_PTY ok`
3. 在 relay 加临时日志，确认 `data` 帧是否在两个方向都有流动
4. 浏览器 F12 → Network → WS → Messages，看帧是否到达

### 4.3 `vim` 花屏 / 颜色不对

```bash
echo $TERM          # 必须是 xterm-256color
echo $COLORTERM     # 必须是 truecolor
```

不对 → 检查 agent 端的 `env` 注入是否生效（见 `03-protocol.md` §6）。
仍花屏 → 大概率是 `resize` 没同步，检查 `setwinsize` 是否被调用。

### 4.4 中文乱码

检查链路中是否有任何一处做了 `decode()/encode()`。协议要求 base64 全程透传，一旦出现文本转换就会在多字节字符中间切裂。

### 4.5 频繁断线

```bash
# 云主机看 relay 日志
journalctl -u remote-pty-relay -f
# 是否出现周期性 1006（异常断开）
```

1006 高频出现 → 中间设备断开空闲连接 → 缩短心跳到 15 s；或调大 nginx `proxy_read_timeout`。

## 5. 退出标准（什么时候应该放弃这个方案）

出现以下任一情况，停止推进并改用公司官方远程方案（堡垒机 / 企业 VPN）：

1. 公司明确书面禁止外联隧道。
2. EDR 对 `python3` 长连接反复告警，或已收到 IT 部门通知。
3. 连接稳定性长期无法满足工作需求（每小时断多次）。
4. 需要访问的数据涉及公司核心机密或个人信息。

技术可行不等于应该做。这条线写在文档里，是为了以后不会被「已经做了一半」推着继续。
