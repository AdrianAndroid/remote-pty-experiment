# 19 · UI 原型

八个界面，覆盖从首次启动到日常使用的全部路径。

设计原则：

1. **列表是主界面**，其余都是它上面的浮层
2. **状态可见**：谁在线、谁在控制谁、用的是不是密文，都要一眼看到
3. **拒绝要说清原因**：未授权 / 缺密码 / 离线，三种文案完全不同

---

## 1 · 主窗口

```
┌─ rpty ───────────────────────────────────────────── relay ● ─┐
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│ 在线节点                                                     │
│                                                              │
│  ●  office-mini     在线 · 可连接             psk            │
│  ◐  home-nas        已连接 · 2 个通道                        │
│  ○  macbook-air     离线                                     │
│  ⊘  old-mbp         在线 · 未授权                            │
│  ●  lab-mac         在线 · 可连接                            │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ ↑↓ 选择   Enter 连接   p 密码   a 添加   q 退出              │
└──────────────────────────────────────────────────────────────┘
```

| 图标 | 含义 | 点击行为 |
| --- | --- | --- |
| `●` | 在线，可连接 | 发起 DIAL |
| `◐` | 当前活跃链路 | 打开通道面板 |
| `○` | 离线 | 置灰，提示"对方未上线" |
| `⊘` | 在线但未授权 | 提示"对方未把你加入白名单"，不重试 |

`psk` 标记表示对方要求密码。**不点进去就能看出来**，避免选错。

---

## 2 · 密码输入

```
┌─ 连接到 office-mini ─────────────────────────────────────────┐
│                                                              │
│  该节点要求密码                                              │
│                                                              │
│  密码  ┌────────────────────────────────────────────┐        │
│        │************************                    │        │
│        └────────────────────────────────────────────┘        │
│                                                              │
│  强度  ████████░░  强                                        │
│                                                              │
│  ☑  记住密码（Keychain）                                     │
│  ☑  允许对方反向控制我                                       │
│                                                              │
│            [ 连接 ]        [ 取消 ]                          │
└──────────────────────────────────────────────────────────────┘
```

- 密码本体进 Keychain，配置文件只留 `psk_required = true` 标记
- 「允许对方反向控制我」默认**不勾**——这是把自己的机器交出去
- 取消不算失败，不弹错误

## 4 · 通道面板（谁在控制谁）

```
┌─ 链路  home-mbp ⇄ office-mini ───────────────────────────────┐
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  我在控制对方                                                │
│    ch 0x0001   shell   main       1.2M ↑  340K ↓             │
│    ch 0x0002   file    ~/build     传输中 62%                │
│                                                              │
│  对方在控制我   !                                            │
│    ch 0x8001   shell   home         0B ↑   12K ↓             │
│                         [ 断开此通道 ]                       │
│                                                              │
│  加密  X25519 + ChaCha20   PSK 已验证 ✓                      │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ [ 断开整条链路 ]                                             │
└──────────────────────────────────────────────────────────────┘
```

**「对方在控制我」必须独立成块并带警示标记**，不能混在同一列表里。这是安全相关的可见性，不能折叠、不能藏进二级菜单。

底部显示加密状态，让用户随时确认"现在走的是密文"。

## 5 · 首次初始化

```
┌─ rpty · 首次初始化 ──────────────────────────────────────────┐
│                                                              │
│  本机标识   office-mini                                      │
│  node_id    a3f2c1d8                                         │
│  指纹       4F-9A-C2-7B-11-DE                                │
│  密钥       ~/.rpty/identity  已生成 600                     │
│                                                              │
│  共享密码（可选，留空表示不设）                              │
│  ┌────────────────────────────────────────────────┐          │
│  │                                                │          │
│  └────────────────────────────────────────────────┘          │
│                                                              │
│  强度  ░░░░░░░░░░  未填                                      │
│                                                              │
│  设了之后，对方想反向控制我时需要它                          │
│          [ 完成 ]        [ 稍后设置 ]                        │
└──────────────────────────────────────────────────────────────┘
```

三件事一次做完：生成密钥、显示身份、可选设密码。

**"设了之后对方才能反向控制我"这句话必须写出来**——这是密码唯一的作用，不说清楚用户会以为它是开机密码。

## 6 · 首次连接（TOFU）

```
┌─ 首次连接 a3f2c1d8 ──────────────────────────────────────────┐
│                                                              │
│  这是第一次连接这台机器。请核对指纹：                        │
│                                                              │
│        A3:F2:C1:D8:4E:9B:2F:07                               │
│                                                              │
│  对方屏幕上应显示同样的值。                                  │
│                                                              │
│  ☐  我已在对方屏幕核对一致                                   │
│                                                              │
│          [ 信任并记住 ]      [ 取消 ]                        │
└──────────────────────────────────────────────────────────────┘
```

- 必须**勾选后才能点"信任"**，防止无脑回车
- 指纹字号放大、独立成行，方便读出来核对
- 只在第一次出现；之后指纹变化才再次弹出（并标红警告）

## 7 · 反向控制请求

```
┌─ 反向控制请求   ! ───────────────────────────────────────────┐
│                                                              │
│  office-mini 请求在你的机器上打开终端                        │
│                                                              │
│  对方      a3f2c1d8                                          │
│  密码      已验证 ✓                                          │
│  会话      22 分钟                                           │
│                                                              │
│  这是你的机器被打开，请确认。                                │
│                                                              │
│       [ 允许一次 ]   [ 一直允许 ]   [ 拒绝 ]                 │
└──────────────────────────────────────────────────────────────┘
```

关键设计：

- **默认按钮是"拒绝"**，不是"允许"
- 「一直允许」写进配置 `auto_accept = true`，但要二次确认
- 显示"密码已验证"——让用户知道技术门槛已过，现在的决定纯粹是人的判断

## 8 · 菜单栏常驻

```
    ┌──────────────────────────────────┐
    │  rpty                            │
    ├──────────────────────────────────┤
    │  ◐ 已连接 office-mini            │
    │    我在控制 2 · 被控制 1         │
    ├──────────────────────────────────┤
    │  打开主窗口            Cmd+O     │
    │  断开链路              Cmd+D     │
    ├──────────────────────────────────┤
    │  退出                            │
    └──────────────────────────────────┘
            ▲  实心 ● = 已连接
```

菜单栏图标三种状态：`●` 已连接 / `◐` 连接中 / `○` 未连接。

**「被控制 1」要常驻显示**。如果只显示"我在控制"，用户永远不知道自己的机器正被谁打开着。

---

## 9 · 状态与文案对照

| 场景 | 文案 | 主按钮 |
| --- | --- | --- |
| 对方离线 | 「office-mini 未上线」 | 置灰 |
| 对方未授权 | 「对方未把你加入白名单」 | 置灰，附"如何添加"链接 |
| 缺密码 | 「反向控制需要密码」 | 输入密码 |
| 密码错 | 「密码不匹配」 | 重输 |
| 握手失败 | 「无法建立安全连接」 | 重试 |
| 指纹变化 | 「⚠ 对方指纹已变化」 | 仅"取消" |

**这六种必须文案不同。** 混成一句"连接失败"，用户会一直点。

## 10 · 交互流

```
   启动
    ├─ 首次 → [5 初始化] → 生成密钥 → 列表
    └─ 非首次 → 连 relay → 拉列表 → [1 主窗口]

   点击 ●
    ├─ 需密码 → [2 密码输入] → 握手
    ├─ 首次连接 → [6 TOFU] → 握手
    └─ 已信任 → 握手
                    ├─ 成功 → [3 终端]
                    └─ 失败 → 文案见上表

   终端内
    ├─ 点底栏通道 → 切换
    ├─ Cmd+T → 新通道（shell / file / forward）
    └─ Cmd+Shift+C → [4 通道面板]

   收到反向 OPEN
    └─ [7 反向控制请求] → 允许 → 对方进入终端

   菜单栏
    └─ [8] → 打开主窗口 / 断开 / 退出
```

## 11 · 技术选型（UI 层）

| 形态 | 方案 | 说明 |
| --- | --- | --- |
| v1 | **本地 Web UI**（`localhost:7700`）+ 系统浏览器 | 最快出效果，xterm.js 直接复用 |
| v2 | 菜单栏 App 壳（Swift 或 Python + `rumps`）包一层 WKWebView | 保留 Web UI，加原生托盘与通知 |
| 不用 | Electron | 体积大，与"轻"的设计取向冲突 |

v1 用 Web UI 的好处：终端、列表、弹框全是网页，一套代码搞定；后续包壳不用重写。
