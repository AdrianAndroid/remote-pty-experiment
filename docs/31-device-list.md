# 31 · 先连中继，再选设备（两层连接）

## 为什么改

原先是「连上 WSS 就等于进了所有机器上的所有终端」：relay 一推 `SESSION_LIST`，客户端就把每条会话都挂上数据通道。于是：

- 没有「有哪些机器可以连」这一屏；
- 两台机器像同一个东西的副本，断开只能连着 WSS 一起断；
- 用户心里的两层（连中继 / 连某台机器）被压成了一层。

用户的原话：**「先连上 wss，然后会出现列表；选中列表一对一连接。断开一对一连接，此时 wss 还连着，应该显示列表才对。」**

## 现在的三层状态

| 状态 | 界面 | 数据通道 |
| --- | --- | --- |
| 未连中继 | 连接页（地址 + token） | 无 |
| 已连中继，未选设备 | **设备列表** | 只有 ctl（收节点上下线），`viewers = 0` |
| 已进入某台设备 | 标签列 + 终端工作区 | 该节点会话的数据通道 |

## 动作表

| 动作 | 结果 |
| --- | --- |
| 连上 WSS | 进设备列表，不 adopt 任何会话 |
| 点某台设备 | 只对该节点开会话通道，进工作区 |
| 「← 设备 ⌘⇧E」 | 撤画面、关该节点通道，PTY 不动，回列表 |
| 「退出中继 ⌘⇧D」 | 断 WSS + 配对断开（另一端一起回连接页） |
| 退出应用 | 断 WSS，PTY 不动 |

WSS 只在三处断开：手动退出中继、退出应用、重连持续失败后用户放弃。进/出设备都不碰它。

## 实现要点

- `relay-client.ts` 新增 `activeNode`：`syncFromList()` 只看不挂（同时把列表塞进 `lastLists` 缓存），只有 `node === activeNode` 才 adopt。因此**列表页的观看开销为零**，但点进去的瞬间能从缓存里立刻挂上，不用等下一轮广播。
- `setActiveNode(node | null)`：切换时把旧节点的会话全部 `closeData` + 清映射（不 kill PTY），再按缓存 adopt 新节点。
- 新增 IPC `node:activate`（ipc / main / preload 三层）。
- 新页面 `screens/devices.tsx`：卡片显示机器名 / 本机徽标 / 终端数 / 离线置灰，空态提示「还没有被控端在线」。
- 侧栏头部的「宿主」改成「设备 + 当前设备名」，顶部加「← 设备 ⌘⇧E」，底部按钮从「断开连接」改成「退出中继」——两个动作现在语义不同，名字必须分开。
- 进设备后「新建终端」不再弹「在哪台机器上开」的选择框：选机器已经是上一屏的事。空设备进入后会自动开一个终端（0.7s 后，先给列表到达留时间）。

## 实测（mini A / mini B / MBP 同一 relay）

| 步骤 | `ctls` | `viewers` | 结论 |
| --- | --- | --- | --- |
| 两客户端连上，停在列表 | 2 | 0 | 列表页不占通道 |
| A 点进 `default`（8 个终端） | 2 | 8 | 只挂这一台 |
| A 点「← 设备」 | 2 | 0 | 回列表，WSS 没断 |
| B 点进空设备 `zhaojiandeMac-mini` | 2 | 1 | 自动新建 1 个终端 |
| A 点「退出中继」 | 0 | 0 | 配对断开，B 显示「另一端已断开连接」 |
| 两端各自「重新连接」 | 2 | 0 | 回到列表，不自动钻进上次那台 |
| A 再进 `default` | 2 | 8 | 8 个标签原样回来、不重复 |

PTY 全程 `shell=80327` 不变；重新进入后输入 `echo AFTER-LIST-ROUNDTRIP shell=$$` 正常回显，说明离开列表只是撤画面。

## 边界

- 设备离线：卡片置灰、标「离线」，点不进去（已开会话的节点掉线仍走原来的 banner 逻辑）。
- 停在列表页时另一端的配对断开照旧生效：整条链路一起断，回到连接页。
- 会话归属、「共享」标记、尺寸锁定的规则一条没动。
