# 32 · 标签有稳定身份，重连后原样回来

## 问题

标签原来只活在渲染层内存里：`leafId` 是进程启动时 `randomUUID()` 出来的，重启就换一个。于是重连 / 重启之后：

- 双击改过的标题被「终端 N」盖回去；
- 顺序按 relay 的 index 重排，跟人摆的不一样；
- 上次选中哪一个丢了；
- 分不清"哪些标签是这个客户端的"，因为身份每次都是新的。

用户要的语义：**同一个客户端重连，标签原样回来；换一个客户端（新 profile），标签是干净的。**

## 做法

给标签一把稳定钥匙：**`sessionId`**（relay 侧的会话身份，PTY 活着它就不变）。`leafId` 退回成"本进程内的通信句柄"，重启可以变，标签身份不变。

按「设备节点 + sessionId」持久化每个标签的元数据：

```json
{
  "default": {
    "active": "<sessionId>",
    "items": [{ "sessionId": "...", "title": "claude-main", "order": 1 }]
  }
}
```

存在 `localStorage['rpty.tabs.v1']`，跟着 userData 走：

- 同一个客户端重启 / 重连 → 读到同一份 → 标题、顺序、选中都回来；
- 换一个客户端（新 profile / 清过数据）→ 没有这份存储 → 干净标签列。

## 关键实现点

- **身份来源**：新建终端时用 `create` 返回的 `sessionId` 认领；镜像别人会话时用 `onAdopted` 事件里的 `sessionId`。
- **落盘时机**：标签列 / 选中变化时的 effect，一次写整份。空列跳过 —— 离开设备、刚进设备还没拿到快照时都是空列，不能让空白覆盖上次记录。
- **恢复时机**：进设备前把存储里那个 `active` 记到 `pendingActiveRef`，等会话挂上来时把它立起来。**必须先落 ref 再 `await activateNode()`**：主进程会立刻按缓存 adopt 并推事件，那时 `useState` 还没生效，只有 ref 知道"这是哪台设备"。
- 恢复时按 `sessionId` 匹配不上的一律不显示：PTY 已经被 kill 的标签不会复活成幽灵。

## 实测

| 步骤 | 结果 |
| --- | --- |
| 把「终端 1」改名 `claude-main`，选中「终端 3」 | store 里 `title=claude-main`、`active=<终端3的 sessionId>` |
| 重启客户端，进 `default` | 8 个标签，第一个是 `claude-main`，选中回到「终端 3」 |
| 新建「终端 9」→ 关掉 → 重启进设备 | 还是 8 个，9 没回来，store 里也只剩 8 条 |
| 重启后 `echo` | PTY 80327 不变，画面接着显示 |

## 边界

- 别人的会话（`owned=false`）走同一套身份，重连后照旧带「共享」标记。
- 关闭标签 = kill PTY，所以它天然不会回来；store 只存还活着的。
- 不做跨机器同步：标签布局是"这个客户端的视角"，不是会话的属性。
