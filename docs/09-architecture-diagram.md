## 2. 分层栈

同一个逻辑，看四层各自负责什么：

```
  ┌ shell ────────────────────────────────────────────────────────────────
  │   一个真实的 /bin/zsh，分配了 controlling tty
  │   vim / htop / sudo 在这一层，它们不知道自己被转发
  ├ pty ──────────────────────────────────────────────────────────────────
  │   forkpty() 产生的 master / slave 一对 fd
  │   负责信号（SIGWINCH / SIGINT）、窗口尺寸（TIOCSWINSZ）
  ├ session ──────────────────────────────────────────────────────────────
  │   PTY 与连接解耦：attach / detach / ring buffer / snapshot
  │   断线时 PTY 继续跑，输出继续进缓冲
  ├ mux ──────────────────────────────────────────────────────────────────
  │   8 字节头：[ver][type][channel:2][len:4]
  │   多通道复用一条连接 + 每通道 256 KB 流控窗口
  ├ crypto ───────────────────────────────────────────────────────────────
  │   X25519 握手 → HKDF → ChaCha20-Poly1305
  │   双向独立 nonce 计数器，防重放
  ├ transport ────────────────────────────────────────────────────────────
  │   wss（生产）/ memory（单测）/ loopback（集成测试）
  │   可替换，上层不感知
  └───────────────────────────────────────────────────────────────────────
```

越往下越"不认识终端"，越往上越"不认识网络"。**这个分界是整个设计的骨架。**

## 3. 一次按键的完整旅程

从按下 `l` 到屏幕上出现 `l`：

```
    Key               Terminal          Relay             Agent             PTY
    │                 │                 │                 │                 │
    ├────── l ───────▶│                 │                 │                 │
    │                 ├─── DATA ch1 ───▶│                 │                 │
    │                 │                 ├──── route ─────▶│                 │
    │                 │                 │                 ├──── write ─────▶│
                                                                            │  zsh 回显 + PTY 渲染
    │                 │                 │                 │◀──── read ──────┤
    │                 │                 │◀── DATA ch1 ────┤                 │
    │                 │◀──── fwd ───────┤                 │                 │
                      │  term.write(Uint8Array)
    │◀──── 上屏 ──────┤                 │                 │                 │
```

六跳，其中四跳是纯转发，两端各做一次编解码与一次加解密。

延迟构成：`家→云 RTT + 云→公司 RTT + 编解码(<1ms)`。所以体验上限由两段物理距离决定，代码优化空间很小——**不要在这上面花时间**。

## 4. 断线重连

这是这个项目最需要"好看"的地方，因为它会发生得很频繁：

```
    PTY               Session           Crypto            Relay             Terminal
    │                 │                 │                 │                 │
    │  ws 断开 → detach
                      │  继续运行, 输出进 ring buffer
                                                                            │  ... 5 min ...
                                                                            │  重连 → 握手
    │                 │                 │                 │◀─── HELLO ──────┤
    │                 │                 │◀──── fwd ───────┤                 │
    │                 │◀──── 协商 ──────┤                 │                 │
    │◀─ attach ───────┤                 │                 │                 │
    │                 │  SNAPSHOT + 64KB ring ─────────────────────────────▶│
                                                                            │  画面恢复
```

对照保守版：断线 → 杀 PTY → 重连是新 shell → 一片空白。
大胆版：断线 → PTY 不知道发生了什么 → 重连 200 ms 内看到断线前的完整画面。

**用户可感知的差异就在这一格。**

## 5. 帧结构

```
  0        1        2        3        4        5        6        7
  ┌────────┬────────┬──────────────────┬──────────────────────────┐
  │ ver(1) │type(1) │   channel(2)     │      length(4, BE)       │
  └────────┴────────┴──────────────────┴──────────────────────────┘
  └──────────────── 8 bytes ──────────────────┘└── payload ──▶
```

| type | 名称 | 用途 |
| --- | --- | --- |
| `0x01` | HELLO | 握手 |
| `0x02` | DATA | 通道数据（含密文） |
| `0x03` | WINDOW | 流控窗口更新 |
| `0x04` | OPEN | 开新通道 |
| `0x05` | CLOSE | 关通道 |
| `0x06` | RESIZE | 终端尺寸 |
| `0x07` | SNAPSHOT | 屏幕回放 |
| `0x08` | CLIPBOARD | 剪贴板 |
| `0x09` | PING | 心跳 |

channel 语义：

```
   ch 0  ─── 控制通道（握手、心跳、session 管理）
   ch 1  ─── shell: main       ┌─ 一个 PTY
   ch 2  ─── shell: build      ┘
   ch 3  ─── file               文件传输
   ch 4  ─── forward            端口转发（默认关闭）
```

一条连接、五个通道、三种用途。这就是"从终端工具升维成 SSH 替代"的具体落点。

## 6. 模块依赖

```
                    ┌─────────────┐
                    │   protocol  │   纯逻辑，零 I/O，零网络库
                    │ frames/mux  │   全部可单测
                    │ session     │
                    └──────┬──────┘
                           │ 只依赖抽象
        ┌──────────────────┼──────────────────┐
        │                  │                  │
   ┌────▼────┐        ┌────▼────┐        ┌────▼────┐
   │ agent   │        │  relay  │        │ client  │
   │ broker  │        │  route  │        │ + web   │
   └────┬────┘        └────┬────┘        └────┬────┘
        │                  │                  │
        └──────────────────┼──────────────────┘
                    ┌──────▼──────┐
                    │  transport  │   memory / ws / loopback
                    └─────────────┘
```

一条硬约束：**`protocol/` 不允许 import `websockets`、`asyncio`、`socket`**。

破坏了这条，单测就跑不动，然后所有验证都要跑到公司机上去，开发速度会掉一个数量级。
