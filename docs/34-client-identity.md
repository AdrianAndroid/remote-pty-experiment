# 34 · 客户端自己起名字，重装才换

## 问题

设备和标签都稳住了，客户端还只是个 uuid：

- 配对断开时另一端只知道"另一端断开了"，两台以上在线时不知道是谁断的；
- 设备列表页说不出"我是谁"，同时开几个窗口排查只能靠猜。

## 规则

首次运行生成 `<主机名短名>-<4 位 hex>`，写进 `<userData>/client-name`，之后每次读回同一个：

```
~/Library/Application Support/rpty-desktop/client-name        → zhaojiandeMac-mini-1620
~/Library/Application Support/rpty-desktop-b/client-name      → zhaojiandeMac-mini-f366
```

**不删数据目录就不变**：重启、断网重连、重新配对都不变；换个 userData（同机多开）各是各的名字；删目录 = 换新客户端，等同重装。

名字只给人看，**归属判定仍然用 `client-id`（uuid）**：改名不会让标签变成「共享」。

## 数据怎么走

| 环节 | 变化 |
| --- | --- |
| ctl 握手 | `wss://…/ctl?token=…&client=<uuid>&name=<name>&primary=1` |
| relay | 记住 `ctl_name[ws]`，`PAIR_CLOSED` 带 `by_name`，`/healthz` 输出 `clients: [{client, name}]` |
| 客户端状态 | `RelayStatus.clientName`，增量事件也带（否则重连后名字消失） |
| 界面 | 设备列表「已连接中继 · 我 · <name>」；断开页「「<name>」已断开连接」 |

老 relay 不认 `name` 时握手参数被忽略，界面退回"另一端已断开连接"，连接本身不受影响。

## 实测（mini 上两个客户端 + 服务器 relay）

| 步骤 | 结果 |
| --- | --- |
| 首次启动 A | 生成 `zhaojiandeMac-mini-1620`，`/healthz` 的 `clients` 里带上 |
| 首次启动 B（另一个 userData） | 生成 `zhaojiandeMac-mini-f366`，两个 ctl 都在线且名字不同 |
| 杀掉 A 重启 | 仍是 `1620`（B 同样不变） |
| 两端都进同一设备，B 点「退出中继」 | A 断开页显示「「zhaojiandeMac-mini-f366」已断开连接」，副文案点名 B |
| 重连后顶栏 | 「已连接中继 · 我 · zhaojiandeMac-mini-1620」不再丢 |

## 顺带修掉的坑

`setStatus()` 的增量状态事件原来没带 `clientName`，导致点「重新连接」之后顶栏的「我 · xxx」消失 —— 已补上。

## 顺手删掉的「本机」

有了客户端名字之后，设备卡片上那个「本机」徽标就没有存在必要了 —— 它原本靠
`node id == 本机主机名短名` 猜，`default` 这类节点明明在同一台机器上却猜不出来，纯属误导。

现在规则很直白：**设备卡片只写设备自己的名字，不再猜"哪台是我"**；"我是谁"由顶栏的
「已连接中继 · 我 · <client-name>」负责。设备名撞车时（比如同机两个 agent 都叫
`zhaojiandeMac-mini`），副行补上节点 id（`0 个终端 · default`）区分，判重也改成按
"人看到的名字"算，`x` 与 `x.local` 不再被当成两台不同名字。

## 设备卡片也换成唯一名

上一版卡片直接写 agent 上报的 `name`（主机名），同机两个 agent 就是两行一模一样的
`zhaojiandeMac-mini`，「本机」又猜不准 —— 等于没标识。

现在卡片标题统一成「主机短名 + 4 位码」，和客户端名字一个格式：

- 节点 id 自带 `<host>-<hex4>` 尾段（agent 自己起的）就直接用那段；
- 节点 id 是人工起的（如 `default`）就按 id 算一个稳定 4 位码（FNV-1a），重启/重连不变。

实测：`zhaojiandeMac-mini 933b`（default 节点）与 `zhaojiandeMac-mini 7b59`，进工作区后
侧栏「设备」也显示同一个名字。

## 顶栏的「我」改成跟设备卡片对上

上一版顶栏写的是客户端自己的码（`zhaojiandeMac-mini-1620`），设备卡片写的是节点的码
（`933b` / `7b59`）—— 屏幕上三套码，用户第一反应是"怎么对不上"。

现在顶栏的「我」不再是客户端码，而是**设备列表里属于本机的那一条**：主进程把本机主机名短名
（`selfHost`）一起给渲染进程，渲染进程按 `agent 上报的 name == 本机主机名` 找那条，用和卡片
完全一样的 `deviceLabel()` 显示。本机没跑 agent 时退回主机短名。

于是 `我 · zhaojiandeMac-mini-7b59` 一定能在列表里找到同一行；客户端全长名（`…-1620`）退到
hover 提示里，只在「谁断开了连接」的提示中出现 —— 那里才是"哪个客户端"需要唯一码的地方。

## 「我」这条不给进

设备列表里**属于本机的那一条**（顶栏 `我 · xxx` 用的同一条）现在：

- 名字后面挂一个蓝色「我」徽标；
- 卡片改成虚线、整体压暗，`disabled`，**不显示「进入 →」**，点了也没反应 —— 自己不需要从自己这儿连回去。

判定沿用顶栏那套：agent 上报的 hostname 与本机主机名短名相等；本机多个 agent 时取"在线且有会话"
的那条当「我」，其余照旧可以进（比如同机的 `default` 节点）。

排序上「我」固定排第一，其余按在线优先 —— 打开列表第一眼就是自己。

## 客户端才是实体（方案 B：宿主由本地 agent 认领）

上一节还在拿主机名猜"哪条是我"。用户否掉了这条路：

> 不应该是按客户端连接 wss 的，不应该是按主机连接 wss 的吧。每个客户端就是一个独立的个体。

于是列表整个换掉：

- 列表标题「在线客户端」，一行一个 **client id**。名字就是客户端自己的固定名字。
- 数据源是 relay 内存里的 ctl 连接（`clients_summary()`），不是节点表。连上才有，断开立刻没，
  不回退成"离线"灰卡 —— 断开要走的是连接页，不是列表里的残影。
- 自己那条标「我」、虚线、没有「进入」，并固定排第一。
- 进入别人后，工作区顶部写**对方的客户端名字**；退出回到列表，对方终端继续跑。

「我这台机器的 agent 是谁」不再靠主机名猜：agent 起来时在 `~/.rpty/agents/` 里开一个
`<node>.sock`（`whoami` 应答）并写 `<node>.json`；客户端连中继前扫这个目录问出来，
握手用 `host=` 报给 relay，relay 记进 `ctl_host`，`CLIENTS` 和 `/healthz` 里带 `host` / `host_name` /
`host_online` / `sessions`。

踩到的坑：同机两个客户端认领到同一个 host，`activeClient` 若按 `host === activeNode` 反查，
就会命中列表里排第一的那条（自己），进别人后侧栏写着"客户端 <我自己>"。改成 `activeClientId`
记住点的是哪个 client id，名字按 id 查。

断开语义也跟着改了：`CTL_LEAVE` 不再广播 `PAIR_CLOSED`，只把自己从列表里撤掉 —— 别人不受影响。

## 配对：从"单向进入"改成"一对一房间"

> 2026-11-28 重写。原文描述的 `CTL_PAIR` 单向进入（A 点一下就把自己塞进 B 的桌面）
> 已经下线 —— 那正是私密房间要防的事。见 `openspec/changes/archive/2026-11-28-pair-as-private-room/`。

现在的建链方式是**通话密码 + 排他房间**（2026-11-28 二次改版：不再要对方点同意）：

- 每个客户端有自己的**通话密码**，缺省 `admin123`，在「我的密码」里改。
  明文存 `<userData>/client-password`（0600），连上 `/ctl` 就 `CTL_PASSWORD` 上报，
  relay 只存 PBKDF2-SHA256 哈希（salt = client id，120k 轮），不落盘、不进日志。
- A 点 B 的卡片 → 输 B 的密码 → `ROOM_JOIN{to, password}`：
  - 密码对 → relay 立刻建房，两边各收一条 `ROOM_OPEN`（`{client, name, host}`），**B 什么都不用点**；
  - 密码错 → 只有 A 收到 `bad_password`，B 完全无感；
  - 对方没上报密码（老客户端）→ `no_password`；对方在房间里 → `peer_busy`。
- 列表卡片上标 `password_default`：还在用 `admin123` 的客户端会被别人一眼看出来 ——
  这是故意的，默认弱口令必须显性化。改过密码的卡片不再有这条标记。
- 房间排他：已在房间里的人既不能被别人连（`peer_busy`），也不能去连别人（`busy`），
  且错误信息不告诉发起者"对方跟谁在一起"。
- 列表上仍然看得到对方，但只挂一个 `busy` / `reconnecting` 标记，**不写对方是谁**：
  第三个人只需要知道点不动，不需要知道谁跟谁在聊。
- 一方断线 → `ROOM_PEER_GONE`，30 秒宽限内重连 → `ROOM_PEER_BACK`；超时或任一方
  `ROOM_LEAVE` → 两边一起 `ROOM_CLOSED`，房间里的终端一起销毁，两个人一起回列表。
- 配对关系不再广播（`pairs_summary()` 返回空表），`CLIENTS` 里没有 `pairs` 字段。

顺带改掉两个会让人误解的动作：

- 工作区底部的按钮从「断开中继」改成「离开 ⌘⇧D」——它只撤画面回列表，不掐 WSS。真要断中继，回列表页点。
- 我进的那个客户端一断开，我这端自动退回列表并提示「「<名字>」已断开中继 · 已回到在线列表」，
  不再卡在一个已经不存在的客户端上、顶栏拿节点名硬凑一个名字。

### 房间一开，两端同时进工作区

房间是双向的，界面也必须是双向的：房子开了，两个人同时进去。

- 两端都收到 `ROOM_OPEN`，主进程把观看范围切到"房间"，界面直接进工作区：
  左侧标签列 = 房间里的全部终端（两边的宿主合并，relay 已按可见域筛过）。
- 侧栏写「通话 <对方名>」+「通话中」徽标，两个人看到的是对称的信息。
- 对方掉线 → 侧栏横幅「对方掉线，正在等它回来（30 秒内）」；回来即恢复。
- 任一方离开 → 两边同时回列表，提示「X 离开了通话」。
- **建房时把两人已有的私有终端借进来**（`Room.borrowed`）：点进去就该看到对面正在跑的东西，
  而不是进一个空房间再让对方现开。借来的散场清掉 `room` 回原主人桌面、PTY 不杀；
  房间里现开的则属于房间，关房一起销毁。判据仍是 `_session_visible()` 一处。

## 一张桌面一套终端（客户端独立，机器共用）

用户要的是「独立的客户端」，不是「独立的机器」：一台机器还只有一个 agent、一套 PTY 宿主，
但每个客户端有自己的桌面 —— 自己的标签、自己的顺序、自己开出来的终端。

- 每个 PTY 记 `owner`（client id）。relay 在 `decorate_sessions` 里已经算过，这次一路带到渲染层。
- 工作区只显示 `owner === 我正站在的客户端` 的行：进别人的客户端看到的是对方的终端，
  不是"我开的那堆"。老数据没有 owner 的照旧显示，免得历史会话突然消失。
- 在房间里按 ⌘T 新建：这台 PTY 属于**房间**（`session.room` 非空、`owner` 为空），
  两边都看得见、都能敲；房间外的人连它的 `session_id` 都收不到。
  默认落在自己的宿主上，自己没有宿主时落到对方的。
- 标签存档（标题/顺序/选中）按 client id 分桶，且只给自己桌面落盘；进别人的桌面不改我自己的存档。
- 「自动建终端」只看这张桌面上有没有终端 —— 别人桌上的终端不算数，否则自己桌面明明空着却不再自动开。
- 连上中继后**停在列表**（`start-at-device-list` 之后的行为）：先看谁在线，再决定进房间还是
  回自己的桌面。「我的终端」按钮在列表页右上角，点进去只看自己名下的私有终端。

## profile：一台机器上开多个客户端

以前「一个客户端」是隐式的：userData 目录是哪个，客户端就是哪个。于是同机双击两次 =
两个进程共用一个 `client_id`（relay 里合并成一行），本地 `owned-sessions.json` 互相覆盖；
要开第二个真客户端只能靠 `RPTY_USERDATA` 环境变量 —— 能用，但不是产品能力：每次要记路径、
不算主窗口、列表里两个名字都是 `<主机短名>-4hex`，像两台不同的机器。

现在把它显式化成 **profile**：

| profile | userData 目录 | 设备列表里的名字 | `primary=1` |
| --- | --- | --- | --- |
| 默认（`default`） | `<appData>/rpty-desktop`（老路径，零迁移） | `<主机短名>-<4 位 hex>`（老规则） | 发 |
| 新建（`client-2`…） | `<appData>/rpty-desktop/profiles/client-2` | `<主机短名>-client-2` | 不发 |
| `RPTY_USERDATA` 老后门 | 指向哪就是哪，名字记作 `custom` | `<主机短名>-custom` | 不发 |

规则与实现要点：

- **入口**：`rpty` 菜单 → 「新建客户端…」（`⌘⇧N`）。自动起名（取现有最大号 +1，不回收空号）、
  建目录、把当前 profile 的 `rpty-config.json` 复制过去（不用重新填地址和 token），
  再 `spawn` 一个 `detached` 的新进程。父子进程互不影响，父进程退出不影响它。
- **同一 profile 只允许一个进程**：`requestSingleInstanceLock()`（作用域就是 userData 目录）。
  第二次启动直接退出，把已有窗口提到前面 —— 不再出现"两个进程抢写同一个 id"。
- **不同 profile 天然并存**：各自一条 `/ctl`、各自一个 `client_id`、各自一套桌面。
  A 里开的终端 B 看不到，这是设计意图。
- **`primary` 语义改成"是不是默认 profile"**：否则新建的每个 profile 都被当副本，
  无主会话的认领顺序会莫名其妙。
- **代码位置**：解析层在 `apps/desktop/src/main/profile.ts`，不 import electron（纯函数，
  `pnpm -C apps/desktop test` 直接断言）；`main/index.ts` 在 `app.setPath('userData')`
  之前调 `initProfile`，窗口标题带上 profile 名，Mission Control 里分得清。
- **与数据面 1:1 的关系**：不同 profile 各自一条 viewer 连接，天然不冲突；
  同一 profile 只允许一个窗口，所以「多窗口共享一条数据连接」这件事暂时不需要做。

踩过的坑：

- 新 profile 目录可能不存在，而 `client-id` / `client-name` 是直接 `writeFileSync` 的 ——
  不先 `mkdirSync` 就会退化成"每次启动换一个身份"。现在启动时无条件建目录。
- 名字一旦写进 `client-name` 就不再变：改 profile 名不会改已生成的客户端名，要改就删那个文件。
