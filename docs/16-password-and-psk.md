# 16 · 密码与 PSK

给客户端加一个共享密码。本文确定：**密码放在哪里、怎么用、能防什么、不能防什么。**

---

## 1. 结论

| | 做法 | 判断 |
| --- | --- | --- |
| ✗ | 登录 relay 时校验密码 | 错。relay 会拿到密码，且密码出现在它可见的通道里 |
| ✗ | 密码写进 URL 或 REGISTER 帧 | 错。同上，还容易进日志 |
| ✓ | 密码作为 **E2E 握手的 PSK** | 对。relay 永远看不到，且同时完成认证与加密 |

一句话：**密码不是"门禁卡"，是"我们俩之间的暗号"。**

暗号只在两个人之间对，门房（relay）不该知道。

---

## 2. 密码的三个作用

```
   ① 认证        证明"我们共享同一个秘密"
                 → 密码错了，握手直接失败，比校验密码更强

   ② 派生密钥    会话密钥从密码派生
                 → 密码本身就是钥匙，不需要额外传密钥

   ③ 防插队      即使有人猜到了 pair_id / 房间名插进来
                 → 没有密码就握不上手，连接被立即断开
```

第 ③ 点很关键：我们的 `pair_id` 和 `node_id` 都不是严格保密的（relay 能看到，也可能被推算）。密码是最后一道闸门。

---

## 3. 密码绝不能出现在哪里

| 位置 | 为什么不行 |
| --- | --- |
| control 连接的 `REGISTER` | relay 明文可读，等于把密码交给门房 |
| data 连接的 URL（`/d/<pair_id>`） | 会进 nginx access log |
| 配置同步 / 备份 | 一旦同步到云盘就等于泄露 |
| 命令行参数（`--password xxx`） | 会进 `ps` 和历史记录 |
| 日志 | 同上 |

**唯一允许出现的地方：本地配置文件（权限 600），以及内存。**

---

## 4. 技术方案

### 4.1 前期：PSK 直出密钥（推荐起步）

不做 ECDH，密码直接派生出对称密钥：

```python
from cryptography.hazmat.primitives.kdf.hkdf import HKDF
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305

def derive_keys(password: str, salt: bytes) -> tuple[bytes, bytes]:
    """salt = min(node_a,node_b) + max(node_a,node_b)，两端算出同样结果"""
    raw = HKDF(
        algorithm=hashes.SHA256(),
        length=64,
        salt=salt,
        info=b"rpty-v1-psk",
    ).derive(password.encode())
    return raw[:32], raw[32:]          # (加密密钥, MAC 密钥)

# 握手
# A → B:  {"type":"HELLO","from":id_a,"ts":...,"mac":hmac(mac_key,"A"+ts)}
# B 校验 mac → 失败即断开 → 成功则回 {"type":"HELLO_ACK",...}
# 之后 DATA 全部 ChaCha20Poly1305(key).encrypt(nonce, payload)
```

约 40 行。安全边界清晰：**只要密码够强，这套就是安全的**。

### 4.2 升级：PSK 认证 + ECDH 前向保密

```python
# 握手改为：
#  A → B: {eph_A, mac_A = HMAC(psk_mac, "h1"||eph_A||ts||id_a)}
#  B → A: {eph_B, mac_B = HMAC(psk_mac, "h2"||eph_B||eph_A||ts||id_b)}
#  session = HKDF(X25519(eph_A, eph_B), salt, "rpty-v1-session")
```

差别：即使密码日后泄露，**过去的流量也解不开**（前向保密）。

何时升级：如果这个工具开始承载真正敏感的内容，或者密码有共享给别人的可能。

> 提醒：手写握手协议不是经过审计的密码学方案。如果要求严格，用 `noiseprotocol` 库（纯 Python 实现的 Noise Framework），或者直接抄它的 `Noise_XX_25519_ChaChaPoly_SHA256` 参数。**不要自己发明新的组合方式。**

## 5. 用户只需要记一个密码

`node_id` 不需要用户操心，首次运行自动生成：

```
   用户要记的：        一个密码（可读，人可抄写）
   程序自动生成的：     node_id（16 字节随机，存在 ~/.rpty/node_id，权限 600）
```

这符合"前期不考虑随机密码"的意图——**用户层面只有一个人能记住的东西**。

第一次启动的流程：

```
   $ rpty init
   ┌──────────────────────────────────────┐
   │  本机标识  office-mini               │
   │  node_id   a3f2c1d8                  │
   │                                      │
   │  设置共享密码（至少 16 位）：           │
   │  > ********************************  │
   │                                      │
   │  配对指纹  4F-9A-C2-7B               │  ← 两台机器输同一密码，指纹一致
   └──────────────────────────────────────┘
```

**配对指纹**是从密码派生的 4 字节短哈希。两台机器各输一次密码后，如果指纹一样，就能用肉眼确认"我们说的是同一个暗号"。

这个小设计能挡住 90% 的"我以为输了同一个密码"的排查时间。

## 6. 密码强度：诚实地说

| 密码 | 效果 |
| --- | --- |
| `123456` | 等于没有。离线爆破毫秒级 |
| `mypassword` | 弱。字典攻击 |
| `office-mini-2026` | 勉强。约 2^50 量级 |
| `correct horse battery staple 24` | 强。推荐这种"多个词拼起来"的形式 |

建议：**至少 16 字符，多词拼接，不用生日/姓名/password 变体。**

前端可以显示强度提示，但**不强制**——这是你的机器，你的取舍。文档里写清后果即可。

---

## 7. 密码不能防什么

必须诚实列出，避免产生虚假的安全感：

| 威胁 | 密码能否防住 |
| --- | --- |
| relay 看到你的连接时间、IP、字节数 | ✗ 不能（这是 TLS 层的事实） |
| 陌生节点向你发 DIAL | ✗ 不能（那是 ACL 的职责） |
| 弱密码导致的爆破 | ✗ 不能（只能靠强度） |
| 你的机器本身被入侵 | ✗ 不能 |
| 中间人伪造 relay | ✓ 能（握手时双方无法伪造对方的 HMAC） |
| 有人猜到 pair_id 插进桥 | ✓ 能（握不上手） |
| 云主机被拿 root 抓包 | ✓ 能（只能看到密文） |

**密码解决的是"内容保密"和"身份确认"，不是"不可见性"。**

---

## 8. 忘记密码怎么办

**不会丢数据。** 因为：

- ring buffer 只在内存（重启即失）
- 没有加密落盘的历史记录
- 没有需要密码解开的数据

所以忘密码 = 重新 `rpty init` 设一个新的，两端都重设即可。代价只是当前所有会话重连。

这是"不做持久化加密"的一个附带好处——**没有密码，就没有密码丢失的成本。**

## 9. 存储

| 阶段 | 方式 |
| --- | --- |
| 前期 | `~/.rpty/config.toml` 里明文，文件权限 `600` |
| 中期 | macOS Keychain（`security add-generic-password`），配置文件只存引用 |
| 后期 | 可选：从 1Password / env 读取，不落盘 |

前期用文件就够，但**必须在 `.gitignore` 里排除 `~/.rpty/`**（这一点已经做了）。

## 10. 多节点时的密码策略

| 场景 | 建议 |
| --- | --- |
| 两台机器（现在） | 一个全局密码 |
| 三台机器 | 先沿用全局密码，简单；任一节点泄露则全线沦陷 |
| 以后要隔离 | 按 peer 分设（`[peer."a3f2"] password = "..."`），一对一密码 |

配置结构预留：

```toml
[node]
name = "office-mini"

[psk]
default = "（全局密码）"

# 以后可选：
# [psk.by_peer]
# "a3f2c1d8" = "只有和 office-mini 用的密码"
```

前期只用 `default`，代码里留好取值的分支点即可。

## 11. 加到哪一层

```
   ┌─────────────────────────────────────────────────────
   │  control 连接（JSON）     无密码
   │    只做 presence 与信令，不承载内容
   │    即使被窃听，泄露的只是"谁在线"
   ├─────────────────────────────────────────────────────
   │  data 连接（二进制）
   │    HELLO 帧  ← 密码在这里用，且只以 HMAC 形式出现
   │    DATA 帧   ← ChaCha20-Poly1305 密文
   └─────────────────────────────────────────────────────
```

密码**只作用于 data 连接的握手与数据**。control 连接不需要密码——它上面没有内容，只有在线状态。

这样即使 control 连接没加密码，也不会泄露任何终端内容。

---

## 12. 一句话

> **密码是你们俩的暗号，不是门房的登记簿。**
> 门房只知道谁进了哪个屋，听不懂你们在说什么；
> 忘了暗号也不丢东西，因为屋里本来就没留字条。
