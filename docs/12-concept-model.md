## 1. 一句话

**一台宿主在跑终端，一台或多台客户端在看它；中间必须经 relay，两端不直连。**

```
  ┌──────────┐              ┌──────────────┐              ┌──────────┐
  │ 客户端 ×N │ ── /ctl ───→ │    relay     │ ←── /agent ── │  宿主 ×1  │
  │ Electron │              │  云上状态机    │              │  Python  │
  │  无 PTY  │ ←─ /d ────── │ 路由 / 发号    │ ──── /d ───→ │  真 PTY  │
  └──────────┘   (数据面)    └──────────────┘   (数据面)    └──────────┘
```

- 客户端**永远不**持有 PTY，也永远不直连宿主。
- 宿主不关心有几个客户端在看（1:N 多播的现状；1:1 变更见 `openspec/changes/data-plane-one-to-one/`）。

### "宿主"是两层，不是一个词

| 层面 | 宿主指什么 | 能不能变 |
| --- | --- | --- |
| **进程层（身份）** | 连 `/agent` 端点 = 宿主进程；连 `/ctl` = 客户端进程 | **不能**。端点不同、代码不同、进程也不同 |
| **会话层（关系）** | `session.node`：这条 PTY 跑在哪台宿主上 | 跟着会话走，但要跟着那条会话一起活 |

一条会话同时挂两个外键：`node`（谁在跑它）和 `owner`（它显示在谁的桌面上）。后者会被认领机制改来改去，前者不动。

**角色不可反转**，这是和旧对称模型的分水岭：`dependencies` 里没有 `node-pty`，客户端没有 PTY 代码；
`relay.py:614` 的 `Node` 只在 `handle_agent` 里创建，`/ctl` 进不了 `self.nodes`。
所以不存在"这个进程对 A 会话是宿主、对 B 会话是客户端"。正确说法是：
**宿主是进程的身份，会话只是记住自己挂在哪个宿主上。**

## 2. 实体（有身份、有生命周期、能单独说"它挂了"）

| 术语 | 代码标识 | 一句话 | 一台机器几个 |
| --- | --- | --- | --- |
| **宿主** | `agent` / `node` | 跑真 PTY 的进程：forkpty、收字节、留回滚 | 1（`RPTY_STATE` 可加到 N） |
| **客户端** | `client` / `ctl` | 桌面 App 进程：画界面、收按键，**不跑命令** | N，每个 profile 一个 |
| **会话** | `session` | relay 侧的一条终端记录：`sid + token + index + owner` | 全局 N（上限 20） |
| **标签** | `tab` / `leaf` | 界面上的一个格子，一个标签对一个会话 | 每客户端 N |
| **观看者** | `viewer` | 数据面上一条正在看某会话的连接 | 每会话目前 N，1:1 后变 1 |

### 会话 ≠ 标签，必须分开说

| | 会话 | 标签 |
| --- | --- | --- |
| 存在于 | relay 状态 + 宿主 PTY | 某个客户端的渲染层 |
| 断线后 | **活着**，回滚继续写 | 关窗即消失（`owned-sessions.json` 留个 id） |
| 身份 | `session_id`（全局唯一、有编号 `index`） | `leafId`（随机、每次启动重来） |
| 换机器看 | 能看到，还是同一条 | 不落盘，别人的桌面不显示在你的标签列 |

混用这两个词，就会得出"标签丢了终端就没了"这种错误推论。

### 客户端 ≠ 窗口 ≠ 桌面

- **客户端**：一个 profile → 一个进程 → 一个 `client_id`。这是隔离单元。
- **窗口**：那个客户端唯一的主窗口（`index.ts` 只 `new BrowserWindow` 一次）。
- **桌面**：别人看到的"你这个客户端有哪些终端"，是视图，不是实体。

"再开一个客户端" = 起一个新进程（`rpty → 新建客户端…`），不是同一个进程里开第二个窗口。
原因：`app.setPath('userData')` 是进程级全局，而四个身份/配置文件全挂在它上面。

## 3. 三个面（说话时指明在哪一层，能省一半解释）

| 术语 | 端点 | 跑什么 | 断了会怎样 |
| --- | --- | --- | --- |
| **信令面** | `/ctl`、`/agent` | JSON：上线、列表、开关会话、resize | 客户端掉线→少一个桌面；宿主掉线→`NODE_OFFLINE` |
| **数据面** | `/d/<data_token>` | 二进制：按键、屏幕字节、快照 | 这个观看者断流，会话本身不受影响 |
| **本地面** | `~/.rpty/agents/<node>.sock` | 一行 JSON：`whoami` | 客户端判定"我没有宿主"，不去猜 |

## 4. 五层身份

按链路顺序背，不要再说"那个 ID"：

```
client_id    谁        userData/client-id         装上就定，删了就是新客户端
client_name  叫什么    userData/client-name        <主机短名>-<4hex> 或 -<profile>
node_id      在哪跑    ~/.rpty/agent.json          <主机名>-<4hex>
session_id   哪条终端  relay 发号 + 落盘            宿主与 relay 各存一份，靠它对账
data_token   凭什么看  控制端生成 UUID            数据面凭据，不暴露 session_id
```

辅助标识：`profile`（数据目录名：默认 / `client-N` / `custom`）、`index`（终端编号，relay 唯一发号）、`leafId`（界面本地标签 id）。

## 5. 关系与状态

| 术语 | 字段 | 含义 |
| --- | --- | --- |
| **配对** pair | `client.pairTo` | 客户端 ↔ 宿主 的绑定 |
| **本机宿主** host | `client.host` | 客户端认领的那台宿主 node id（可能为空） |
| **认领** claim | `session.owner` | 无主会话归到哪个客户端 |
| **主客户端** primary | `claimant_primary` | 默认 profile 那个，优先认领无主会话 |
| **拥有** own | `session.owner == client.id` | 这条终端算"我的"（决定标签落不落盘） |
| **在线** | `*.ws is not None` | 只看有没有活的连接，**不代表会话还在** |

## 6. 禁用说法 → 替换

| 别这么说 | 改成 | 为什么 |
| --- | --- | --- |
| "一个窗口一个 agent" | 一个客户端一个窗口；宿主是另一层，可能根本不存在 | 混淆了进程层与宿主层 |
| "终端"和"标签"混着说 | 终端 = PTY 进程；会话 = 云端记录；标签 = 界面格子 | 三者生命周期完全不同 |
| 单说 "agent" | 说"宿主" | 和 AI agent 撞名，且看不出指进程还是角色 |
| "多开" | "多 profile" 或 "多标签" | 前者是进程隔离，后者是同窗口多终端 |
| "同看" | "1:N 多播"（已定死要砍） | 该能力已被 1:1 变更取消 |
| 用"节点" / "主机" / "服务器"指宿主 | 统一叫宿主 | 一物多名是沟通卡壳的主因 |

## 7. 与旧模型的差异（读老文档时对照）

| 旧文档（10 / 12 原文 / 14 等） | 现在的现实 |
| --- | --- |
| 对称 peer，人人可当宿主 | 单向：宿主跑 PTY，客户端只看 |
| bridge：两 peer 直连打隧道 | 必须经 relay，两端都主动外连 |
| channel：一 session 对 N 通道共享 | viewer：一 session 对 N 观看者（即将 1:1） |
| DIAL 信令 | 已删除，换成 `/ctl` + `/agent` + 广播 |
| 角色按 session 决定 | 角色按进程决定：宿主进程 / 客户端进程 |

保留的洞察只有一条：**"谁能看谁"是关系，不是安装包属性** —— 客户端能进任何在线宿主的桌面，
宿主也不关心客户端是谁。

## 8. 术语在代码里的落点

| 术语 | 代码符号 | 位置 |
| --- | --- | --- |
| 宿主 | `class Node` | `server/relay.py:100` |
| 客户端 | `class Client` | `server/relay.py:122` |
| 会话 | `class Session` | `server/relay.py:143` |
| 观看者 | `class Viewer` | `server/relay.py:158` |
| 会话（宿主侧） | `class Session` | `agent/rpty_agent.py` 第 60 行附近 |
| profile | `resolveProfile` / `initProfile` | `apps/desktop/src/main/profile.ts` |
| 标签 | `leafId` / tabs | `apps/desktop/src/renderer/src/App.tsx` |

同一术语在 relay 和 agent 里各有一个 `Session` 类，是**同一条终端的两侧投影**：
relay 那份管归属与编号，agent 那份管 fd 与回滚。对话时说"会话"默认指 relay 那份。
